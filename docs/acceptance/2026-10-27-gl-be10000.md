## 测试环境说明

- 上行是无线中继（`apclii0`，私网 192.168.50.0/24），只有 IPv4，**没有全局 IPv6**。
- 路由器本机直连访问 `https://1.1.1.1`、`1.0.0.1`、`162.159.36.1` 的 443 端口全部超时（80 端口、`www.cloudflare.com` 正常）。core v0.3.0 的 IPv4 探测只用 `https://1.1.1.1/cdn-cgi/trace`，所以在这条线路上**探测必然失败**（见 F2）。
- 经用户同意，创建/更新/无变化周期这几项用了**临时中转**：路由器上加一条仅运行时的 `iptables -t nat OUTPUT` 规则，把发往 1.1.1.1:443 的 TCP 转到验收用 Mac 上的 `socat`（只接受路由器来源），TLS 仍端到端、证书照常校验。此时探测到的是 Mac 代理的出口 IP（日本），不是路由器 WAN 的 IP。重启前删除了规则并确认已删除，重启后的检查没有中转。
- 中转期间约 60 轮里有 2 次探测超时（中转/代理抖动），下一轮自行恢复。
- UI 通过真实的 uhttpd `/ubus` JSON-RPC 路径验证：SSH 上 `session create` 一个 rpcd 会话，按 rpcd 登录时的展开规则只授予 `luci-app-cfddns` 和 `luci-base` 两个访问组（读写），再从 Mac 发出与页面 JS 相同的调用。没有浏览器和 root 密码，**页面渲染未验证，留给用户**。

## 缺陷与发现

- **D1（缺陷）在 LuCI 清空 Token 后，`/etc/cfddns.env` 仍保留旧 Token。** 步骤：服务启用并运行时，在“基本设置”取消“启用”，清空 Token 和域名，点“保存并应用”（`apply(false)`：commit → disable → stop → `cfddns-config`）。预期：设备上不再有 Token；“运行状态”显示尚未配置。实际：服务停止、取消自启、页面报“服务已停止并已取消开机自启，但配置无效：cfddns-config: token is required”，但 `/etc/cfddns.env`（`0600`）仍是旧的 `CFDDNS_TOKEN`、`CFDDNS_V4`、`CFDDNS_PERIOD`；页面里 `cfddns -inspect` 继续用这个已删除的 Token 查询旧域名并显示“找到记录”，命令行 `cfddns -once` 也仍可用它写记录。原因：`cfddns-config` 只在配置有效时替换 env（`net/network/cfddns/files/cfddns-config:129-145`），`apply(false)` 在生成器失败时不处理 env（`luci/applications/luci-app-cfddns/htdocs/luci-static/resources/cfddns/service.js:156-167`）；README 第 87 行写的是“每次 start / reload 覆盖”。验收收尾时按用户决定手动删除了该文件。
- **F2（core 限制，不属于本软件源）IPv4 探测只用 `https://1.1.1.1/cdn-cgi/trace`**（core `internal/ip/detect.go:155`），没有备用地址。在这台路由器的中国大陆直连上行上，1.1.1.1 / 1.0.0.1 / 162.159.36.1 的 443 端口不通，而 `https://www.cloudflare.com/cdn-cgi/trace` 可用；结果是 daemon 永远探测不到 IPv4，也就不会更新记录。需要 core 层面决定是否增加按主机名访问的备用 trace（同样强制 tcp4）。
- **F3（说明）rpcd 对不带参数的 ACL 条目放行任意参数。** rpcd `file exec` 先按可执行文件路径检查，匹配就不再看参数，所以 `/usr/libexec/cfddns-config` 这一条允许带任意参数执行。`cfddns-config` 不读参数，实际无影响；但“ACL 只列精确命令”只对带参数的条目成立。调用方传入的 `env` 也会被 rpcd 传给 root 进程（已实测，属于已接受的风险）。
- **F4（次要）daemon 的所有日志都以 `daemon.err` 级别记录**（包括 `unchanged` / `updated`），因为 procd 把 stderr 记成 err。
- **F5（次要，文档）README 命令行配置示例 `uci set cfddns.main.token='…'`** 会把 Token 放进进程参数和 shell 历史；验收时改用 `uci batch` 从 stdin 读入。
- **F6（环境）GL 固件的 dropbear 会关闭来自 WAN 侧的 SSH**（“Connection closed”）。重启期间验收 Mac 自动连到了上游 Wi-Fi，SSH 同样被关闭，重新连回 GL-BE10000 的 Wi-Fi 后恢复。之前两台路由器“拒绝 SSH”很可能也是这个原因。

## 偏离

- 创建/更新/无变化周期这几项使用了用户同意的临时中转（见上文），探测到的是中转出口 IP。
- Token 一律经 stdin 用 `uci batch` 写入，没有按 README 的 `uci set` 写法。
- 做 C12 检查时，曾为 `grep -f` 在路由器 `/tmp`（tmpfs）临时放过一份 `0600` 的 Token 副本约 2 分钟，随即删除，之后整机重启也清空了 tmpfs；后续检查都改为从 stdin 读取。
- 同版本强制重装（U2）只作参考，不算升级验证。
