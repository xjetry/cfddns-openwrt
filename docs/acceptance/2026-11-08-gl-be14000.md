## 测试环境说明

- 这是用户的主路由，上行 PPPoE（`pppoe-wan`），有原生 IPv6（全局 /60 和 /64）。验收用 Mac 在它的 LAN（192.168.8.0/24）上。
- 路由器本机访问 `https://1.1.1.1/cdn-cgi/trace` 和 `https://[2606:4700:4700::1111]/cdn-cgi/trace` 都超时（curl 8 s 上限）；`https://www.cloudflare.com/cdn-cgi/trace` 走 IPv4 0.12 s、走 IPv6 0.50 s 正常。正好覆盖 core v0.3.1 的备用 trace。
- Cloudflare 看到的 IPv4 与 `pppoe-wan` 上的地址不同（同一 /16，运营商出口转换），与路由器上 `curl -4` 访问 trace 得到的地址一致。cfddns 发布的是 Cloudflare 看到的地址，这是正确行为。IPv6 探测结果是 `pppoe-wan` 上的一个全局地址。
- 这条线路上 GitHub 的 IPv6 不稳定：`raw.githubusercontent.com` 走 IPv6 超时；`xjetry.github.io` 走 IPv6 时有时停在 2.52/2.62 MB 不动，有时 `Connection reset by peer`；IPv4 正常。见 F7。
- 按用户决定**不重启**，也不改网络、防火墙、DHCP、系统配置，不重启网络服务；本次没有任何中转。
- UI 通过真实的 uhttpd `/ubus` JSON-RPC 路径验证：SSH 上 `session create` 一个 rpcd 会话，按 rpcd 登录时的展开规则只授予 `luci-app-cfddns` 和 `luci-base` 两个访问组（读写）。表单的暂存按设备上 `uci.js` 的 `save()` 发出 `uci delete {options}` / `uci set {values}`；保存并应用、运行状态按钮和状态读取则直接运行仓库里的 `service.js` / `status.js`（用仓库测试的 `tests/js/luci_vm.cjs` 加载），它们的每个 rpc / fs 调用都转发到设备的 `/ubus`。设备上 `/cgi-bin/luci/` 在 :80 和 :8080 都返回 403，GL nginx 的 `/ubus/` 返回 302，没有浏览器验证。

## Cloudflare 测试记录

- 测试前：`test.o1.pw` 没有任何类型的记录（`total_count 0`）。
- 测试中：daemon 首轮创建 A 和 AAAA；面板侧（API）把两条改成 192.0.2.30 / 2001:db8::30 测更新；临时加过一条重复 A 记录 192.0.2.10，随后删除。
- 测试后：全部删除，`total_count 0`，与测试前一致。

## 缺陷与发现

本次没有发现新的软件缺陷。D1（清空凭据后 env 残留 Token）和 F2（IPv4 探测只用 `1.1.1.1`）在本机上复验通过（L13–L15、E1–E4）。

- **F7（环境）这条线路上 GitHub 的 IPv6 不稳定。** `opkg install cfddns` 和 `opkg install luci-app-cfddns` 第一次都因下载失败退出 255（`opkg_download: … wget returned 4`），原样重跑成功。单独测试：`uclient-fetch` 每次随机选 IPv4 或 IPv6 地址，走 IPv6 时有时 `Connection reset by peer` 或长时间停住；IPv4 正常。验收时 README 没有提到下载失败时重试；随本验收记录一起提交的 README 改动在 GL-BE14000 的“未验证”一行里写明了这一点（第一次下载失败，原样重跑即成功）。「安装」一节本身仍没有重试说明，可以以后再补。
- **F8（次要，提示文字）只清空两个域名时，“尚未配置”提示后面带的 core 细节是 `cfddns -token is required`。** 原因：生成器删除了 env，`-inspect` 读不到任何配置，core 先检查 Token。提示的主体（“请填写 Token 和至少一个域名”）是对的，细节会让人以为 Token 丢了（`status.js:429` 原样显示 inspect 的 stderr）。
- **F9（外观）服务未在 procd 注册时，`/etc/init.d/cfddns stop` / `restart` 在 stderr 打印 `Command failed: Not found`，退出 0。** rc.common 的标准行为；`service.js` 只看退出码，页面不显示。
- **F10（次要，文档）README 安装步骤留下 `/tmp/cfddns.pub` 和 `/tmp/cfddns-Packages.sig`**（公开数据，tmpfs，重启清除），没有提示删除。验收收尾时删除。
